## Overview
In this learning module, you will:
* Gain a general understanding of what UART is
* Understand common examples of where UART is typically used
* Follow the flow of data through the UART module
* Learn how to use the UART module with the DMA module

## Introduction
The Universal Asynchronous Serial Transmitter (UART) module is a single-ended, asynchronous serial communication port that transmits (TX) and receives (RX) a programmable length serial bit stream into and out of the device at a programmable rate (called a "baud rate"). UART communciation occurs without the need for a shared clock signal. It also requires only 1-2 physical pin connections between the communicating devices. It can be configured to do half-duplex communication (single direction communication), or full-duplex communication (bidirectional communication). The UART is typically used for communication with a serial terminal or communication between two processors, and it has the option of using receive and transmit FIFOs (First-In-First-Out) for reducing servicing overhead.

## Common Applications of UART
### Processor-to-Processor Communication
Two devices can communicate with each other if they both have peripherals capable of transmitting/receiving data with the UART protocol. Because of this, a C2000 device with a UART peripheral can communicate with other C2000 devices, other TI devices, or 3rd party devices as long as they have a UART peripheral.

### Processor-to-PC Communication
One common use case of the UART peripheral is to display debugging messages to a COM port on a PC. This data is displayed in ASCII so that it is human-readable. This is useful for debugging purposes when JTAG cannot be used.

### Low-Speed, Long Distance Communication
Transceivers can be used for low-speed long-distance UART communication. They convert the single-ended UART signals from the device into differential signals, commonly using a RS-232, RS-422, or RS-485 protocol.

## Why use UART?
UART is often selected because of its simplicity, and compatibility with other devices. Some other advantages are:
* In the default configuration, there is no notion of commander or responder, so either device can be used to initiate transmission. However, if commander/responder functionality is needed, the UART module has a 9-bit multiprocessor mode that can be utilized.
* Separate data lines for each device allow for data to be sent and received simultaneously and independently.
* The fractional baud rate divisor of the C2000 UART module allows for more fine-tuned baud rates than the SCI module.
* The UART module has DMA access, so UART messages can be sent and received without any CPU intervention. 

However, there are also many other forms of serial communication that can be used, and some possible drawbacks to consider when using UART:
* Higher likelihood for error from clock inaccuracies between the two communicating devices, since the clock signal is not shared.
* Slower maximum transmission speed than most other communication peripherals. 
With a general overview of UART use established, we can get into what UART is and how it works.

## What is UART?
### UART Frame Structure
Both the transmitting and receiving line of the UART module operate using the same frame structure. In an idle state, a UART line is logic level high. The start of a UART frame pulls the signal low for one “bit width”. Then, the data bits pull the UART line high or low depending on their logical levels. A parity bit follows, which also could pull the line high or low for one “bit width” of time. At the end of the transmission, either one or two stops bits will pull the line high, depending on the configuration.

### UART Baud Rate
Both devices communicating must have the same configured baud rate, which is measured in bits per second, and decides the UART “bit width”. The UART module transmits and receives these bits at the configured baud rate, which is generated by the SYSCLK clock source.

There are two types of error that can be introduced when two devices are communicating via UART. The first is a known error associated with the configured baud rate and clock speed combination. This error can be attributed to whether or not the baud rate is an even factor of the clock speed, or how close to an even factor it is. It is generally recommended to select a clock speed and baud rate combination that will result in a known error as close to 0% as possible. The UART Sysconfig can be used to calculate this error, as shown below.

The second type of error that can be introduced is any sort of inaccuracy with the oscillator that is associated with real world factors, like temperature, age of the device etc. This inaccuracy cannot be calculated and is in most cases negligible.  

### UART FIFO Operation
Enabling FIFO mode of the UART module can optimize the speed at which data can be transmitted or received. Both the UART transmitter and the UART receiver have an associated FIFO with a depth of 16. Both FIFOs can be configured to trigger at a specific fractional level full. For the UART transmitter, an interrupt will be triggered when the transmitter has the FIFO trigger level number of bytes full, and therefore is available to be written to with (1 - trigger level) amount of new data. For the UART receiver, an interrupt will be generated when the receive FIFO contains the FIFO trigger level number of bytes full, and therefore is available to be read trigger level number of characters from. 

For example, if the configured FIFO level for the UART TX FIFO is 7/8 and the configured FIFO level for the RX FIFO was 1/8, the TX FIFO will trigger an interrupt when it is 14 elements or less full and the RX FIFO will generate an interrupt when there are 2 characters or more present. In the TX interrupt, 2 characters can be written to the TX FIFO in the ISR. In the RX interrupt, 2 characters can be read from the RX FIFO in the ISR. The following would be the flow of data:

### Viewing UART Debugging Messages
In order to view UART messages in the COM port of a PC, a physical UART to USB bridge is required. On the launchPAD and ControlCard for some devices, this bridge is provided and the TX and RX signals from the UART module on the c2000 device are converted and routed through the USB connection on each board. For devices where this routing is not included for the UART signals (for example on F2838x controlCARD), you must wire up a UART to USB bridge externally in order to view UART messages from a COM port on your PC.

## Using UART with DMA 
The UART module is commonly used for debugging purposes in an application. In the development phase, a user may want to transmit and receive these debugging messages without effecting the normal application performance. This is where the DMA module comes into play. The DMA has the ability to transfer data directly from the device memory (for example from an array) to the UART data register or from the UART data register to a location in device memory without using the CPU. In the same way that the TX and RX FIFO trigger levels can be used to trigger interrupts on the CPU when the FIFOs contain a certain number of characters, these FIFO levels can also be used to trigger burst transfers of the DMA. When using the DMA to transfer transmit data to the UART data register or transfer receive data from the UART data register, the DMA burst size should match the number of characters written or read with each trigger. In the below example, 2 bytes will be written/read to/from the TX/RX FIFO with each DMA burst transfer.

## Test Your Knowledge!
**Question 1**

Which is a benefit of the UART module over the SCI communication peripherals?

a. DMA access – can communicate without CPU intervention

b. High-speed communication rates

c. Highly accurate transmission – reduced chances of dropped packets

d. Can be configured to use more than one different communication protocol 


```{dropdown} Answer
a. The UART module’s main benefit is DMA access. Its maximum transmission speed is less than that of the SPI and I2C peripherals, and it cannot be configured to use any other communication protocol other than the UART protocol (as opposed to the LIN module for example, which could do UART communication or LIN communication).
```

**Question 2**

Which of the following that are pins used in the UART protocol?

a. UARTCLK

b. UARTTX

c. UARTRX

d. UARTDR

```{dropdown} Answer
b and c. The UART peripheral only requires two physical pin connections, one for transmitting (TX) and one for receiving (RX).
```

**Question 3**

If you want to trigger an interrupt every time 2 bytes can be read from the RX, which configuration should be used (ignoring the TX FIFO level configuration)?

a. UART_setFIFOLevel(myUART0_BASE, UART_FIFO_TX1_8, UART_FIFO_RX1_8);

b. UART_setFIFOLevel(myUART0_BASE, UART_FIFO_TX1_8, UART_FIFO_RX2_8);

c. UART_setFIFOLevel(myUART0_BASE, UART_FIFO_TX1_8, UART_FIFO_RX6_8);

d. UART_setFIFOLevel(myUART0_BASE, UART_FIFO_TX1_8, UART_FIFO_RX7_8);


```{dropdown} Answer
a. In order to read 2 received characters in each RX ISR, an interrupt should be triggered every time there are at least 2 characters present in the RX FIFO. So, a 1/8 trigger level should be used.
```

**Question 4**

If you want to trigger an interrupt every time the TX FIFO is available to be written with 4 characters, which configuration should be used (ignoring the RX FIFO level configuration)?

a. UART_setFIFOLevel(myUART0_BASE, UART_FIFO_TX1_8, UART_FIFO_RX1_8);

b. UART_setFIFOLevel(myUART0_BASE, UART_FIFO_TX2_8, UART_FIFO_RX1_8);

c. UART_setFIFOLevel(myUART0_BASE, UART_FIFO_TX6_8, UART_FIFO_RX1_8);

d. UART_setFIFOLevel(myUART0_BASE, UART_FIFO_TX7_8, UART_FIFO_RX1_8);

```{dropdown} Answer
c. In order to trigger an interrupt every time there are 4 characters available (or in other words when the TX FIFO has at least 4 bytes empty), an interrupt should be configured to trigger when there are 12 characters (or less) present in the FIFO. So, a 3/4 trigger level should be used.
```

## Summary
From this module, the key takeaways are:
* The UART IP uses a UART protocol, which is a standard asynchronous protocol using 2 pin connections and a shared baud rate.
* The main applications of the UART protocol are device to device communication, COM port debugging during application development, and low speed/long distance communication.
* FIFO and DMA operation can be used to increase the performance of the UART module.
